RagaM-Roll — Help

RagaM-Roll — a play on "Rock and Roll" — is a Carnatic-notation playground. Type srgm notation on the top left; see the textbook-style line and the ragamroll (a pianoroll-style roll — the app's signature view) on the top right; hear it, retune it, and browse ragas & talas.

The panes

  • Editor (left): your srgm source. It auto-compiles as you type (off the main thread, so it never freezes).
  • Ragamroll (top-right): the ascii roll; the playing row highlights during playback.
  • Notation (bottom): the Carnatic-textbook single-line form with barlines.
  • Drag the dividers between panes to resize.
  • Sung lanes (beside the roll): the written swaras and the sahitya of a piece that has been aligned — see The sahitya and the written swaras.

Writing srgm — the melody

The melody uses a deliberately tiny alphabet so it stays terse:

TokenMeaning
s r g m p d nThe seven swaras. Case picks the variety — lower vs upper is the komal/shuddha (lower/higher) form, resolved against the current raga.
> / <Prepend to a swara to raise / lower the octave, e.g. >s, <p. The shift persists for the notes that follow.
2, 4, …An integer after a swara sets its length, e.g. s4. Default is 1.
zA rest (silence). Takes a length too: z2.
-A separator (visual grouping; no time).
%A line starting with % is a comment.

Cutting repetition

DirectiveMeaning
L=2Default note-length multiplier: absLen = L × the number on the swara. So S2 G2 M2 P2 N4 can be written L=2 S G M P N2.
O=5Set the absolute octave register.

Directives — the setup line

These appear once or a few times, so they read verbosely for clarity:

DirectiveMeaning
Raga=mohanam,0The raga (name) and a semitone transpose of Sa. The raga fixes how each swara letter resolves to a pitch.
Tala=adi,4The tala (cycle) and a length resolution — chosen so the shortest note in the piece is an integer 1 (one akshara = N length-units).
T120Tempo in BPM.
I[FLUTE]Instrument (General-MIDI name) for export.

Example

% A short Mohanam phrase
Raga=mohanam,0  Tala=rupaka,2  T160
L=1 O=5
G2 G2 P4 P4  D2 P2 >S4 S4

Playing & the mixer

The transport row (above the panes) holds:

  • ▶ ⏸ ⏹ play / pause / stop. The ragamroll highlights the current row as it plays.
  • Sa the reference pitch — Auto follows the raga, or pin Sa to a note (C4–C6). Transposes playback.
  • ♩ tempo a speed slider (0.2× steps) plus an exact-BPM box; ↺ returns to the composition tempo.
  • 🎶 Drone, 🎼 Melody, 🔊 Tala, 🔈 Master — each icon is a mute toggle (keeps its set level); sliders set volume. Mute melody to solo tala + drone.
  • 🎻 Timbre the melody voice: Soft, Bowed, or Reed.

Volumes are live during playback. Tempo, Sa transpose, and the scale override apply on the next Play.

Open, Save, Export

  • Open ▾ — load a bundled example or a .srgm file from your device.
  • Save — download your source as .srgm.
  • Export MIDI — a standard .mid of the melody (12-EDO; the microtonal scale override is web-audio only).

Ragas & Talas

  • Ragas — a searchable reference of the raga scales (swaras, intervals in semitones).
  • Talas — each tala as a row of akshara boxes with accents marked (X = sam, o = anga start). ▶ plays the cycle as strums and lights each box in time.

Scale ⚙ — experimental microtonal tuning

Override the playback pitches with an authentic 53-EDO tuning built from the 72 melakartas:

  • Pick a mela (grouped by the 12 chakras) — or tap Match piece to jump to the mela matching your raga.
  • Each of R, G, M, D, N shows its variety and an a / b comma toggle — the two microtonal shrutis a comma apart. Defaults to the just-intonation-nearest.
  • The table shows the resulting swaras, 53-EDO steps, and cents. Apply retunes playback; ↺ returns to the plain 12-EDO ragabase.

The tuning affects web-audio playback and the drone only — notation and MIDI export stay unchanged.

Pitch-curve gaps — clarity & bridge

A break in the cyan pitch curve means those frames were marked unvoiced (frequency = null). If you hear a clear note where the curve is broken, it is almost always the clarity gate or the bridge setting — not a bug.

What nulls a frame

  • Clarity gate (default 0.85): every frame whose pitch-detector clarity falls below the threshold is dropped as unvoiced. Clarity dips exactly where you still hear a clear note — during gamaka and fast slides (the waveform is momentarily less periodic), at note onsets and consonants, in soft or breathy passages, and where the tanpura drone / reverb bleeds in. The sound is there; the detector's confidence fell, so the frame is gated out. This is the usual cause of "audio present, curve broken".
  • Bridge gap (default bridge-ms 250, span ±5 shrutis): a null gap is filled in only when it is both ≤ 250 ms long and ≤ 5 shruti-steps end-to-end. A longer gap, or one across a big pitch jump, is left open — so a ~300 ms unclear stretch stays a visible break.
  • Out of range (below 50 Hz or above 1200 Hz) — rare for voice.

Tuning it

Clarity and bridge-ms are live sliders in pitchy — but they only take effect when you load the audio fresh (Choose File), because that is when the per-frame clarity data exists. A shared link opens with only a downsampled contour and no clarity data, so the sliders can't re-gate there — until you re-choose the original mp3 (Choose File): if it matches the shared source, pitchy upgrades to the full-resolution contour (keeping your notes) and the sliders work again. A different file loads for playback only. Lower the clarity threshold (~0.7–0.8) for fewer gaps (but noisier frames); raise bridge-ms (~400–500) to bridge longer gaps. Trade-off: some gaps are real (breaths and silences between phrases) — over-bridging invents pitch across them.

Gamaka from the curve — does opening a link change the notation?

No. Opening a shared link (or an auto-detected session) does not re-derive or overwrite the notation's gamaka. Each note in a link carries an explicit gamaka — the pitch contour over that note's span, sampled at full resolution when the notation was made. On open it is applied to the note unconditionally and kept verbatim.

The Gamaka checkbox ("gamaka from the curve") only fills in a gamaka for notes that don't already have one — by sampling the pitch curve across the note. Since every note from a link already has one, the toggle does nothing to them, and turning it off does not strip the existing gamakas.

It matters only when you add or redraw a note while editing: that new note has no gamaka, so with the toggle on it gets one sampled from the curve. Caveat: a shared link carries a downsampled contour (≤ 450 points), so a gamaka newly derived in a link session is coarser than the originals. To derive new full-detail gamakas, re-choose the original mp3 (Choose File): if it matches the shared source, pitchy upgrades to the full-resolution contour and keeps your notes; a different file loads for playback only. Either way the notes that came from the link already carry their full-resolution gamakas.

Editing notes on the roll

The roll beside the notation is directly editable — move, resize, and create notes on the grid. (This was once a separate draw page; it is the app's own roll now.)

  • Start from a raga: on a new/blank piece, picking a raga fills it with that raga's notation (curated if available, else the auto-detected draft with gamakas, else a plain scale) — a starting point to edit.
  • Select a note or a rest: tap (or click) it. That is all it does — it stays on the roll, and whatever applies to the thing you are pointing at (Delete, most of all) becomes available.
  • Edit a note's gamaka: double-click (or double-tap) the note to open its pitch-curve editor. Coming back with ‹ Back leaves it still selected.
  • Delete a note or a rest: select it and press Delete (or the Del / Backspace key, except while you are typing in the srgm box). The token is removed and the piece gets shorter — unlike dragging an edge, which trades the time with a neighbour and leaves the piece the same length.
  • Move a note's pitch: on a touch screen, long-press a note (~⅓ s) to grab it, then drag sideways; on a desktop, just press and drag a note. Pitch snaps to the raga's swara rows. The following notes keep their own pitch.
  • Move the boundary between two notes: drag the handle at either end of a note. The two notes share out the time between them and what you hear does not change — the pitch the neighbour was carrying, ornament and all, is taken up into this one. Push far enough and the neighbour is gone, its line still sounding, now written as part of this note. The top edge trades with what came before, the bottom edge with what comes after; the note you are holding is never the one that disappears. This is the repair for a phrase that pitchy cut in two where the singer did not — from whichever side of the boundary you happen to grab.
  • Make a note simply last longer: hold Shift and drag either handle. That changes only the note you grabbed — it gets longer or shorter, the notes after it move along, and nothing next to it is altered. On the bottom edge the handle follows your pointer. On the top edge it stays put and you pull: a note's start is fixed by everything that came before it, so the handle cannot move, and how far you drag away from it is how much the note opens by. Shrinking stops at one akshara and never removes anything; use Delete for that. (The last note needs no Shift — nothing follows it to trade with, so its bottom edge always did this.) Durations snap to the tala's akshara pulse everywhere.
  • Split one note into two: Ctrl (or ⌘) +Shift-click inside a note, or Alt-click — the same gesture pitchy uses. The cut lands on the nearest akshara and both halves keep the original pitch, so the pair sounds exactly like the note did. Nothing is heard to change; only where the boundary is written. Drag the new top edge back to undo it by hand, or press Undo. A click with no room on one side is refused rather than moved.
  • Absorb a silence: dragging a note's top edge back over the rest before it takes that time into the note, and the silence becomes the transition between the note before and this one — the line runs from one pitch to the other instead of jumping. To keep a break, resize the rest instead of absorbing it.
  • Create a note: tap + note, then drag on the grid — pitch snaps to a raga row, length to the akshara. Painting over a rest fills it, past the end appends (the note lands where you drag, with a leading rest), over a note splits it.
  • Add a rest (silence): in + note mode, paint in the narrow rest lane at the far left of the grid — it inserts a rest of the length you drag.
  • Resize the grid: drag the handles at the pitch axis's two ends to widen/narrow the pitch range (by whole raga rows), and the handle at the bottom of the time axis to lengthen/shorten the empty grid. A blank piece opens with a small grid — stretch it out to make room to write.
  • Gamaka on move: moving a note that carries a gamaka keeps the sound unchanged by default (the note relabels); a toast lets you switch that move to carry the curve to the new pitch instead. The gamaka on move control sets the default.
  • Draw a gamaka on the roll: tap ✎ gamaka, then drag across a note to trace its pitch curve — right there on the roll, so you can see the notes around it (is it a descent or an ascent?). Zoom in first with the pitch handles + expand for room. Tapping a note still opens the full-screen curve editor when ✎ gamaka is off.
  • Edit a gamaka's points: in ✎ gamaka mode, drag a point to move it, tap a point to remove it, tap the curve line to add a point. Removing the last points clears the curve. Everything is undoable (Undo / Ctrl-Z), including an accidental Clear.
  • Re-trace a curve that already has one: hold Shift and drag across the note. Once a note carries a gamaka, an ordinary drag always moves the nearest point — at normal zoom a note is only a couple of dozen pixels tall and a trace begins right where its first point sits, so there is nowhere left to press that means "start again". Shift says which you meant.
  • Where a point lands: with snap on, on the 53-EDO grid — the same lines the roll draws, all 53 of them, not just the raga's own notes. An ornament moves between the notes, so it needs the finer grid. Turn snap off and a point goes exactly where you put it; the notation carries two decimals, so it survives being saved and reopened.
  • The grid bounds are a view convenience — they aren't saved; the notes and rests you write are.

Sharing a piece, and opening one from elsewhere

Share copies a self-contained link: the whole notation, deflated and packed into the URL's # fragment. Fragments are never sent to a server, so the piece travels from your browser to the reader's and nowhere else — nothing is uploaded and nothing is stored anywhere. Open ▾ → Open link takes one back, from this or any other host.

Opening a link replaces what is in the editor, names it shared, and clears the fragment so your later edits are not overridden the next time you reload. It never starts playing on its own.

Writing links from another program: the format is a short one — UTF-8, zlib deflate, base64url, behind a pako: prefix — and it is specified, with reference implementations in JavaScript and Python and a test vector, in docs/open-in-ragamroll.md. Any program that can produce srgm can hand a piece straight to this app.

The instrument

The Pluck voice is not a preset — it is a string, a body and a room, and the ⚙ beside the voice picker opens them: how bright the string is, how long it rings, how hard it is picked, a little drive, the three resonances of the body, damping, room and level.

  • It is live. Turn something while a phrase repeats — nothing stops — and that is the only way an instrument is really judged. With nothing playing, each change strikes a note so you can hear it; ♪ asks for one on demand.
  • Sustain is a time, and the same time at every pitch: six seconds rings under the hand, one second is stopped almost as it speaks. Damping is how much of the top the body absorbs, so right is more.
  • The body resonances do not follow the note. A box rings where it rings whatever is played on it, and that fixed response is most of what separates an instrument from a waveform — it also means the same setting sounds different at a different Sa.
  • The settings are remembered for this browser, and they follow the piece into the lane editor.
  • ⭳ Save writes them to pluck-settings.json. To make a setting the one everybody gets, drop that file in the repo and run node tools/apply-instrument.mjs pluck-settings.json --apply, which folds it into the built-in instrument rather than leaving anyone to hand-edit a number.
  • ⭱ Load reads one back. Settings are remembered per browser, so a file is how an instrument survives another machine, another browser, or cleared storage. It is applied whole and takes effect at once — including the settings with no slider. A file written by an older build still loads: anything it does not carry stays at the built-in value and the panel says which. A file with a setting this build has never had is refused entire, and nothing changes.

The sahitya and the written swaras

Notation converted from another system often arrives with that system's own written swaras and the sahitya (the lyrics) sitting above the notes, as %@ and %$ lines. Those lines say what is sung; nothing in them says which note carries it. Deciding that is a judgement of the ear, one note at a time — so it has a page of its own.

Open the lane editor → (also reachable at /lanes.html)

What it shows

  • The ragamroll on its side: time runs left to right, pitch up the lane on the raga's own shruti rows, each note's gamaka drawn through it at the pitch it actually reaches. It is only as tall as the piece's range.
  • Below it, the written swaras and the sahitya as loose beads waiting to be placed, and the tala across all three lanes — the avartana in terracotta with the anga starts and the akshara pulse under it, and each cycle numbered in its own ruler above the source's %BB block labels.
  • The notation below that, which is exactly what a Save would write, updating as you place groups. It is editable, and it has the same read and source toggles the app's editor has.

Placing a group

  • Work left to right. The frontier note is ringed in gold — one per lane, since the two move independently. Click a bead, shift-click a later one to take the whole run, then Attach (or Enter) to bind that group to the frontier note. A group belongs to exactly one note.
  • Ctrl-click the last bead of a run — or the last note of it in the roll — and the whole run is bound at once, one bead per note. Most of a piece runs note for note; binding those one at a time is typing out a decision already made.
  • Leave empty (Space) passes over a note: nothing is sung there. For a long stretch — whole sections of a varnam have no sahitya, the swaras being the syllables — click the lane's name to aim at it, then shift-click the last note of the stretch. What was left empty stays drawn as a thin bar.
  • A syllable that runs across two notes: drag the right edge of an attached sahitya bead to show it still sounding past its note, or press Carry – on the note it runs into — which says the syllable continues, rather than that the note is silent.
  • Taking work back: Detach last (Ctrl-Z) unwinds the end; alt-click a bead takes that lane back from its note on; alt-click a note in the roll, or click it and press Detach from here, takes both lanes back. It has to take what follows — those groups were placed against this one.

Hearing it

  • Play, with a playhead across all three lanes, a mixer, a listening speed independent of the piece's own tempo, and a choice of instrument that takes effect mid-phrase.
  • Click the ruler to set A, shift-click for B: play begins at A and turns back at B, so pressing play again plays the same phrase again. Pause holds its place; rewind returns to A.
  • The tala starts silent and the drone barely on — a strum on every akshara is exactly what buries the gesture you are judging. Levels, speed, zoom and the A/V trim are remembered for this browser.

What the alignment is written as

The result goes on the notes themselves, as two attributes:

<D2{gka:"((S↑ N<<)S↑)D",swara:"N D",sahitya:"ro",gcurve:[…]}

swara: is the written swaras of the source notation for that note (several, space-separated, where one ragamroll note takes a whole gesture's worth), and sahitya: the syllables. A lone - means the previous syllable is still being sung on this note. Nothing plays them — not the audio, not the MIDI, not the roll's geometry; they are carried so they can be shown.

The %LANES line

One JSON object on a comment line, holding what the attributes above cannot say — the state of the work rather than its result. Every other reader skips it.

%LANES {"sw":115,"sa":115,
        "grow":{"sw":{},"sa":{"4":8.36,"9":0.57,…}},
        "ins":{"sw":[],"sa":[[5,"-"],[12,"-"],…]},
        "ab":[null,null]}
keywhat it holds
sw / sathe frontier in each lane — the index of the next note to be filled. It is the only record of a leave empty: those notes carry no attribute, so without it the work would resume before them.
growsustains, per lane, by bead index → extra length in units. "4":8.36 = the fifth sahitya bead keeps sounding 8.36 units past its note. Rounded to two decimals so the file stays readable.
inscarried beads, by position → text. [5,"-"] = a - was inserted at bead 5. Recorded here rather than written into the %@ / %$ lines, because those are the other system's own text, hand-aligned in columns a rewrite would flatten.
abthe A–B rehearsal region in length-units, null when unset.

Delete the line and you lose the frontier, the sustains, the carries and the marks — but not the alignment itself, which lives on the notes. The editor would re-derive a frontier from the last attached note and carry on. Note the order on load: insertions are replayed before the note attributes are matched back to beads, or every group after the first carry lands one note off.

Reading it in the app

  • A piece carrying an alignment shows it beside the roll — two columns, each group against the note it is sung on, with the playhead crossing them. A piece carrying none shows nothing, and no control for it.
  • The lanes' own buttons sit in the band across the top of the roll: which side of the roll they sit on, which column leads, and away. Only the way back is in the roll's strip, and only while they are hidden.
  • A syllable is drawn at the top of its cell, because the consonant is struck at the note's onset and it is the vowel that stretches through the rest.
  • The app is a reader here: editing an alignment is the lane editor's job.
